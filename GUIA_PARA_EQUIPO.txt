NASA EXPLORER


1. ¿DE QUE TRATA LA APLICACION?

NASA Explorer hecha con Kotlin y
Jetpack Compose. Reune publicaciones astronomicas y eventos publicados
por servicios de NASA en una sola interfaz. La app permite explorar
APOD, objetos cercanos a la Tierra, eventos naturales EONET, actividad
espacial DONKI, guardar favoritos y consultar explicaciones con un
asistente conectado a un backend propio.

La aplicacion no es un producto oficial de NASA. NASA publica los datos;
NASA Explorer los presenta y facilita su consulta.

Funciones principales:
- Inicio con accesos a los modulos y feeds recientes de DONKI y EONET.
- APOD: imagen o contenido multimedia astronomico del dia, explicacion
  y detalle.
- NeoWs: asteroides cercanos, rango de fechas, busqueda, filtros,
  ordenamiento, estadisticas y detalle.
- Mapa EONET: eventos naturales activos con marcadores y detalle.
  Las ubicaciones de geometrias complejas son aproximadas.
- Favoritos de APOD y asteroides, guardados localmente con Room.
- Ajustes de tema e idioma persistidos localmente.
- Asistente contextual con historial local. El modelo se consulta desde
  el backend y las respuestas no deben tratarse como datos oficiales.


2. COMO ESTA ORGANIZADO EL CODIGO

Ele proyecto separa responsabilidades en capas:

presentation
  Contiene pantallas Compose, ViewModels, estados de interfaz y
  navegacion. Solicita datos a repositorios; no define directamente
  las solicitudes HTTP de cada pantalla.

data
  Contiene las fuentes de datos: servicios REST y DTO, base de datos
  Room, preferencias y repositorios que conectan esas fuentes con la
  presentacion.

domain
  Contiene calculos de negocio que pueden probarse sin interfaz, como
  filtros, ordenamientos y estadisticas de asteroides.

ui
  Contiene componentes visuales compartidos, traducciones de interfaz,
  colores, tema y tipografia.

Flujo tipico:
Pantalla Compose -> ViewModel -> Repository -> API o almacenamiento
local -> Repository -> ViewModel/StateFlow -> pantalla.

6. ¿QUE ES local.properties?

local.properties es un archivo local de configuracion de Android Studio.
En este proyecto app/build.gradle.kts lo lee para obtener:

NASA_API_KEY
  Clave para las solicitudes NeoWs y DONKI. Para pruebas se puede usar
  DEMO_KEY, que tiene una cuota reducida; cada desarrollador puede usar
  su propia clave NASA.

AI_BACKEND_URL
  URL base del backend del asistente. En el emulador Android, el valor
  http://10.0.2.2:8000/ apunta al puerto 8000 de la computadora anfitriona.
  En un telefono fisico se debe usar una direccion accesible desde ese
  telefono o la URL HTTPS del backend desplegado.

local.properties.example es una plantilla sin claves reales. Se copia
como local.properties y se completan los valores adecuados al entorno.
No se debe enviar local.properties a Git, adjuntarlo en chats ni incluirlo
en un paquete publico.

IMPORTANTE SOBRE SEGURIDAD:
Aunque NASA_API_KEY se lee desde local.properties, Gradle la incorpora a
BuildConfig. BuildConfig no protege secretos: una clave NASA de cliente
puede extraerse del APK. No poner claves privadas en Kotlin, BuildConfig
ni local.properties. La clave de OpenRouter debe existir unicamente en
el entorno del backend, configurada como OPENROUTER_API_KEY.


7. BACKEND DEL ASISTENTE

backend/main.py
  API FastAPI. Valida la pregunta y el contexto, construye instrucciones
  para el modelo, consulta OpenRouter y devuelve una respuesta. Incluye
  GET /health y POST /api/assistant/explain.

backend/requirements.txt
  Dependencias de Python para ejecutar el servicio.

backend/.env.example
  Plantilla de las variables de entorno del backend. Se configura una
  copia local llamada backend/.env con OPENROUTER_API_KEY y, opcionalmente,
  OPENROUTER_MODEL. Ese archivo real es privado y no se comparte.

El backend es independiente de Android. La app envia la pregunta y el
contexto NASA mostrado; la clave del proveedor de IA se queda en el
servidor.

Para ejecucion local, desde la raiz del proyecto, consulta la seccion del
backend en README.md. En general, se instala backend/requirements.txt,
se copia backend/.env.example como backend/.env y se configura la clave
privada; luego se inicia Uvicorn con:

uvicorn main:app --app-dir backend --host 0.0.0.0 --port 8000


8. PERMISOS, DATOS Y LIMITES

app/src/main/AndroidManifest.xml
  Declara el permiso INTERNET y la actividad de inicio. El permiso es
  necesario para NASA, el backend, los mapas y las imagenes remotas.

Room guarda favoritos e historial en el dispositivo. DataStore guarda
las preferencias de tema e idioma. EONET, DONKI, APOD, NeoWs y NASA Images
son servicios separados; si un servicio falla, los otros pueden seguir
funcionando.

Las mediciones de asteroides y las explicaciones de eventos proceden de
sus fuentes. El asistente puede interpretar los datos, pero su respuesta
no es una publicacion oficial de NASA ni debe usarse como prediccion.
